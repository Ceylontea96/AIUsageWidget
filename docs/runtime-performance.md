## Cursor 탐색을 화면 처리에서 분리

Cursor 활동 감시는 변경 전에는 Tk의 주기 콜백에서 직접 파일을 탐색·읽고 JSON을 처리했다. 프로젝트와 대화 로그가 많으면 이 시간 동안 다른 화면 이벤트가 대기한다. 같은 감시 로직을 단일 백그라운드 스레드에서 실행하도록 변경했다.

- 스레드는 Cursor 감시가 처음 필요할 때 시작한다. 이전 작업이 끝나기 전에는 새 작업을 겹쳐 실행하거나 큐에 계속 쌓지 않는다.
- 파일 및 활동 상태는 작업 스레드가 소유한다. 화면 스레드는 갱신 필요 여부와 활동 만료 시각만 받으며, 작업 스레드는 Tk를 호출하지 않는다.
- 활동 만료 시각을 전달하므로 탐색이 느려지더라도 화면에 활동 상태가 영구히 남지 않는다.
- 서비스를 끄면 대기 중인 결과를 무효화한다. 다시 켰을 때는 새 상태로 탐색하며, 비활성화 전 결과를 화면에 적용하지 않는다.
- 창을 닫을 때 느린 디스크 작업을 기다리지 않는다. 진행 중인 단일 작업은 끝나는 대로 종료되고, 후속 작업은 수행하지 않는다. 파일 시스템 호출 자체를 강제로 취소하는 방식은 아니다.
- 정상 감시 요청 간격 0.75초와 전체 재탐색 정책은 유지한다. 완료 결과는 다음 활동 콜백에서 반영하므로 실제 앱에서는 완료 후 통상 최대 약 0.25초의 반영 대기가 추가될 수 있다.
